# Hub Unified Inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Android app that captures every notification through a `NotificationListenerService`, stores it locally, and shows it as a BlackBerry-Hub-style chronological inbox in Material 3 Expressive, with swipe triage, snooze, search, settings and two home-screen widgets.

**Architecture:** Single `app` module, Kotlin + Jetpack Compose, MVVM over a Room-backed `HubRepository` exposed through Hilt. The listener service in `capture` feeds the repository; `ui` renders it with Paging; `snooze` schedules wake-ups with `AlarmManager`; `widget` renders Glance widgets from the same repository. Task 1 (scaffold) and Task 2 (data contract) are sequential; Tracks A–D are independent and run in parallel in separate git worktrees, then merge.

**Tech Stack:** AGP 9.3.1 (built-in Kotlin), Kotlin 2.3.20, KSP 2.3.6, Gradle 9.5.0, Compose BOM 2026.02.01, Material 3 (Expressive where the resolved version offers it), Room 2.7.1 (+FTS4), Paging 3.5.3, DataStore Preferences 1.1.1, Hilt 2.60.1, Navigation Compose 2.10.2, Glance 1.2.0, Robolectric for JVM tests of Room and Android classes.

**Spec:** `docs/superpowers/specs/2026-11-01-hub-inbox-design.md` (read it first; the mockups are `docs/mockups/screens.html`).

## Global Constraints

- `namespace` and `applicationId` = `com.iwankurnia.hub`; `minSdk 26`, `compileSdk { version = release(37) }`, `targetSdk 37`.
- British English in every UI string, comment and doc; American spelling only in code identifiers.
- Nothing leaves the phone: no network permission, no analytics.
- Verification is `./gradlew :app:assembleDebug` and `./gradlew :app:testDebugUnitTest`; no emulator. Device checks happen at the end on Iwan's phone over adb.
- Material Symbols Rounded for every icon (`androidx.compose.material.icons.rounded.*`; where a symbol is missing from the extended icon set, add it as a vector drawable in `res/drawable`). No emoji anywhere in the UI.
- Seed colour `#0B57D0`; snoozed bar `#E5A900`, snoozed chip `#FFE2A8` on `#4A3200` text; unread bar = `MaterialTheme.colorScheme.primary`.
- Tabs are exactly All · Unread · Deleted. Swipe right = Read, swipe left = Delete. No flag/star anywhere. No compose/FAB.
- Commit per task on the track's branch with Conventional Commits; never push. Branches: `main` for Tasks 1–2, then `track/capture`, `track/list`, `track/sheet-search-settings`, `track/widgets`.
- Each track touches only the files its task lists; shared files (manifest, catalog, DI modules, nav graph, strings) are fully written in Tasks 1–2 and are **not** edited by tracks except where a task says so explicitly.

## Review Focus

1. A messaging notification re-posted with the same three messages plus one new one must create exactly one new item, never duplicates of the three (Track A, test `capture_dedupesExistingMessages`).
2. A notification removed because the app cancelled it marks the item read; one swiped away in the shade does not (Track A, test `removal_appCancelMarksRead_userCancelDoesNot`).
3. Swiping Delete then tapping Undo within the snackbar window restores the item to ACTIVE with its original `sortAt` (Track B, test `undoDelete_restoresItem`).
4. A snooze that ends while the phone is rebooting still fires: `BootReceiver` reschedules the next due snooze (Track C, test `bootReceiver_reschedulesNextSnooze`).
5. The per-app count widget with more apps than fit must show the N most recent and never overflow its row (Track D, test `appCountWidget_truncatesToWidth`).
