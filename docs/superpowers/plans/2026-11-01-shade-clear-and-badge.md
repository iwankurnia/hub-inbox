# Keep the status bar clear; unread badge on the launcher icon

Iwan's requests, 2026-11-01, on top of the snooze/sheet removal.

1. "When I read a notification, dismiss it from the notification centre." Already true: `HubViewModel.open`, the read swipe, select-mode Read, Mark all read and the widget's Read chip all call `LiveActions.cancel(key)`. Add one view-model test if any of those paths lacks a cancel assertion; otherwise nothing to build.

2. **Option to hide notifications from the status bar.** A Behaviour setting "Keep the status bar clear" (subtitle "Hub removes each notification from the shade as soon as it has captured it"), default off, stored in `HubPrefs.clearShade: Flow<Boolean>` + `setClearShade`. In `HubListenerService.handle`, after a successful `repository.capture` (result `Inserted`/`Updated`, not `Ignored`) and after `registry.register(sbn)`, if the pref is on call `cancelNotification(sbn.key)`. The registry keeps the content `PendingIntent`, so "tap opens the app" still works afterwards. Never cancel Hub's own notifications (they are filtered out before capture anyway). Tests: `posted_withClearShade_cancelsAfterCapture` and `posted_withoutClearShade_leavesShade` in `HubListenerServiceTest` (record cancels through the existing canceller seam).

3. **Unread badge on the app icon.** Android launchers badge an app from its own notifications, so Hub posts one silent summary notification of its own: channel `"unread"` (name "Unread count", `IMPORTANCE_LOW`, `setShowBadge(true)`), id `1`, small icon `ic_stat_hub` (restore the drawable if the removal deleted it), title "Hub", text "N unread notifications" (plural string), `setNumber(n)`, `setOnlyAlertOnce(true)`, `setSilent(true)`, not ongoing, content intent `HubIntents.open(context, tab = "UNREAD")` with `FLAG_IMMUTABLE`. Post it whenever the unread count changes and is > 0; cancel it when the count reaches 0. Drive it from one place: a `@Singleton UnreadBadge` class collecting `repository.unreadCount()` on an application-scoped coroutine started from `HubApp.onCreate` (and the listener service, which may start without the activity). Gate it behind a Behaviour setting "Unread badge on the app icon" (subtitle "Shown through a silent Hub notification"), default on, `HubPrefs.unreadBadge`. On Android 13+ this needs `POST_NOTIFICATIONS`: keep the permission and the onboarding request; if the permission is missing, skip posting silently. The listener's own-package filter already keeps this notification out of Hub's list. Tests: `UnreadBadgeTest` with Robolectric's `ShadowNotificationManager`: `postsWhenUnread`, `cancelsAtZero`, `offWhenSettingDisabled`.

Docs: add both settings to spec 4.8 and the badge to a new 4.12 "Launcher badge"; README one line each. Commits: `feat(capture): option to clear the shade after capture`, `feat(badge): unread count on the launcher icon`, `docs: shade option and launcher badge`. Build gate as before; no emulator.

4. **Multi-select app filter.** The filter sheet lets Iwan tick several apps. `HubFilter.packageName: String?` becomes `packageNames: Set<String>` (empty = every app); `HubViewModel.packageFilter: StateFlow<Set<String>>` with `toggleApp(pkg)`, `clearFilter()`; DAO paging queries take `(:all OR packageName IN (:pkgs))` with `all = pkgs.isEmpty()` (Room expands the list; pass the set as a list). `unreadCount` for the tab badge follows the filter the same way. `AppFilterSheet`: "Every app" row clears the set and closes; app rows toggle a tick (`Checkbox` or a trailing check icon) and stay open; a "Done" text button at the bottom closes. The active-filter chip under the tabs reads "Only WhatsApp" for one app, "WhatsApp, Teams" for two, "N apps" for three or more, × clears all. `HubIntents.EXTRA_PACKAGE` (widget app tap) selects just that app. Search's own chip row may stay single-select. Tests: `filterApps_toggleAndClear` in `HubViewModelTest`; `pagedItems_filtersByPackageSet` in `RoomHubRepositoryTest`; update the fakes. Commit: `feat(list): filter by several apps at once`.
